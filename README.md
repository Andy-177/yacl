# Yet Another Config Language

**YACL**是一种轻量、易读的配置语言。

它在保持 YAML 可读性的同时，借鉴了 TOML 的显式引号规则，并引入了独特的引用系统和多行字符串处理方式。

文件扩展名：`.yacl` 或 `.ycl`

## 快速概览

```yacl
# 基本键值对
姓名: '张三
年龄: 30
身高: 1.75
激活: true
角色: none

# 嵌套对象
人员:
    地址:
        城市: '北京
        邮编: 100000

# 列表
爱好:
    - '阅读
    - '游戏
    - '徒步

# 列表项是对象，对象内部又含子列表
服务:
    - 名称: 'api
      端口: 8080
      白名单:
          - '10.0.0.1
          - '10.0.0.2

# 引用
当前城市: [人员].[地址].[城市]   # 结果为 "北京"
第一个服务: [服务].0.[名称]      # 结果为 "api"
```

## 语法详解

### 键（Key）

- **所有键均为字符串** —— 无需为键添加引号。
- 键可以包含除 `:` 和 `[` / `]`（这些符号用于引用）之外的任意字符，也可以包含空格（建议避免特殊符号以保持清晰）。
- 键区分大小写。

### 值（Value）

#### 字符串

YACL 提供了 **四种** 字符串表示方式：

| 定界符 | 行为说明 |
|--------|----------|
| `'...` （单引号，**不闭合**） | 从开头的 `'` 开始，**直到行尾**的所有内容被视为字符串字面量。**即使出现 `#` 也不会被当作注释**。 |
| `"...` （双引号，**不闭合**） | 与单引号类似，但 **`#` 会开始注释** —— 字符串在行内第一个 `#` 处结束（或到行尾）。 |
| `''' ... '''` （三个单引号） | 多行字符串。**所有内容**（包括 `#` 和换行）均为字面量。开头/结尾的换行会被修剪（见[多行块](#三引号块)）。 |
| `""" ... """` （三个双引号） | 多行字符串，但 **包含 `#` 的行会被移除该符号及其之后的内容**（即 `#` 及该行 `#` 之后的部分会被移除，但行本身保留，`#` 之前的内容保留）。其余换行保留。 |

**示例：**
```yacl
a: '这一整行都是字符串，即使有 # 和特殊字符
b: "只有这部分是字符串，# 之后的内容是注释（被忽略）
c: '''
    多行
    包含 # 号
    和换行
    '''
d: """
    这一行保留
    配置: # 这一行的 # 及之后内容被移除
    这一行也保留
    """
```

对于 `d` 的结果为：
```
这一行保留
配置: 
这一行也保留
```

#### 数字

- 整数：`123`、`-456`
- 浮点数：`3.14`、`-0.001`

无需引号。

#### 布尔值

以下词元被识别为布尔值（**区分大小写**，请使用小写形式）：
- `true`、`false`
- `on`、`off`
- `enabled`、`disabled`

#### 空值

词元 `none` 表示空（null）值。

### 列表（数组）

- 列表以行首的 `-`（短横线）引入。
- **缩进决定嵌套层级**：属于同一个列表的所有 `-` 必须对齐在同一列；子层必须比父层缩进更深。
- 列表项可以是任意类型的值：字符串、数字、布尔值、`none`、**对象**，以及**子列表**。

**基本示例：**
```yacl
水果:
    - '苹果
    - '香蕉
    - '橙子
```

`-` 后面的内容（或后续更深缩进的内容）决定了这一项的类型，共有四种形态：

| 写法 | 该项的类型 | 示例 |
|------|-----------|------|
| `- 值` | 标量 | `- '苹果`、`- 42`、`- true` |
| `-`（单独一行） | 由后续更深缩进的内容决定 | 子行以 `-` 开头 → 子列表；子行是 `键: 值` → 对象 |
| `- 键:` | 对象 | 键的值在后续更深缩进的行展开（常用于值本身是列表或对象） |
| `- 键: 值` | 对象 | 键值写在同一行，适合简单标量值 |

> 提示：`-` 单独成行与 `- 键:` 是同一套缩进规则的两种写法，可互相改写（见下文对照）。

#### 列表项为对象

当 `-` 后面紧跟 `键:` 时，这一项就是一个**对象**，而不是字符串。

```yacl
level1:
    - level2:
        - hello
```

等价 JSON：

```json
{
  "level1": [
    {
      "level2": [
        "hello"
      ]
    }
  ]
}
```

也就是说：`level1` 是一个列表，列表只有一项；这一项是一个对象，对象的键 `level2` 的值又是一个列表，其中只有一项 `"hello"`。

**缩进规则：**

- `- ` 之后的第一对键值对，属于该项对象。
- 该对象内的其余键，必须与 `- ` **之后的第一个键**对齐（而不是与 `-` 对齐）。
- 键的值如果是列表 / 对象，则继续在更深一层缩进展开。

```yacl
服务:
    - 名称: 'api
      端口: 8080
      白名单:
          - '10.0.0.1
          - '10.0.0.2
```

等价 JSON：

```json
{
  "服务": [
    {
      "名称": "api",
      "端口": 8080,
      "白名单": ["10.0.0.1", "10.0.0.2"]
    }
  ]
}
```

**等价写法：** 把 `-` 单独写一行，键放到下一行（缩进更深），语义完全相同：

```yacl
level1:
    -
        level2:
            - hello
```

两种写法产生的值都是 `[{"level2": ["hello"]}]`，可按可读性择一使用；本文档统一用 `- 键:` 写法。

#### 子列表（嵌套列表）

列表项本身也可以是列表，只需让该项的 `-` 后面不再写值，并把内层列表写在更深缩进处：

```yacl
矩阵:
    -
        - 1
        - 2
        - 3
    -
        - 4
        - 5
        - 6
```

等价 JSON：

```json
{
  "矩阵": [
    [1, 2, 3],
    [4, 5, 6]
  ]
}
```

`矩阵` 是一个包含两个列表的列表，每个内层列表含三个数字。

**判定要点：**

- 外层 `-` 单独一行 → 该项由后续更深缩进的内容构成。
- 紧跟着的更深缩进行若以 `-` 开头 → 该项是**子列表**；若以 `键:` 开头 → 该项是**对象**。
- 子列表的 `-` 必须比它所属的 `-` 缩进更深；若缩进相同，则会被解析为**同一层的兄弟项**，而不是子列表。

**对比：**

```yacl
# 子列表：一个列表项，值是 [1, 2, 3]
单元素:
    -
        - 1
        - 2
        - 3

# 兄弟项：三个并列的标量项
三个元素:
    - 1
    - 2
    - 3
```

前者等价 `{"单元素": [[1, 2, 3]]}`，后者等价 `{"三个元素": [1, 2, 3]}`。

#### 多层嵌套

子列表与对象可以任意交替嵌套，层级完全由缩进表达，不需要额外的括号。

```yacl
组织:
    - 名称: '研发部
      小组:
          - 名称: '前端
            成员:
                - 'Alice
                - 'Bob
          - 名称: '后端
            成员:
                - 'Carol
```

等价 JSON：

```json
{
  "组织": [
    {
      "名称": "研发部",
      "小组": [
        {
          "名称": "前端",
          "成员": ["Alice", "Bob"]
        },
        {
          "名称": "后端",
          "成员": ["Carol"]
        }
      ]
    }
  ]
}
```

**引用嵌套结构**（索引一律使用裸数字）：

```yacl
第一个小组: [组织].0.[小组].0.[名称]        # => "前端"
第一个成员: [组织].0.[小组].0.[成员].0      # => "Alice"
```

### 对象（映射）

- 对象由键值对组成，通过**缩进**嵌套（空格或制表符均可，但需保持一致）。
- 没有显式的结束标记，缩进范围决定作用域。
- 对象同样可以作为列表项出现，此时对象的第一个键写在 `- ` 之后（见[列表项为对象](#列表项为对象)）。

```yacl
配置:
    超时: 30
    重试次数: 3
    服务器:
        主机: 'localhost
        端口: 8080
```

### 引用

YACL 允许**引用**配置中的其他值。语法如下：

- `[键名]` 访问当前对象中的键。
- `.`（点号）用于链式访问。
- `[索引]` 访问列表元素（索引从 0 开始）。  
  **重要：** 当数字**不**带方括号时，它被视为列表索引；当数字在方括号内时，它被视为字符串键。

**示例：**
```yacl
人员:
    姓名: 'Alice
    年龄: 30
    爱好:
        - '阅读
        - '游戏

# 引用
人员姓名: [人员].[姓名]          # => "Alice"
第一个爱好: [人员].[爱好].0     # => "阅读" （裸数字表示索引）
第二个爱好: [人员].[爱好].[1]  # 也可用方括号，但这里 [爱好] 是列表，所以 [1] 也视为索引（如果键 "1" 不存在）
```

*注意：列表索引请使用裸数字（如 `.0`）；若使用 `[0]`，它会被当作字符串键 `"0"`，可能不存在于列表中。*

引用同样可以沿着“列表 → 对象 → 子列表”一路链式访问：

```yacl
服务:
    - 名称: 'api
      白名单:
          - '10.0.0.1

首个白名单: [服务].0.[白名单].0   # => "10.0.0.1"
```

### 注释

- **单行注释：** `#` —— 从 `#` 到行尾的内容被忽略，**除非**它出现在单引号字符串（其中 `#` 是字面量）或三个单引号块内。
- **多行注释：** `### ... ###` —— 两组三个井号之间的所有文本被完全忽略，可跨多行，可出现在任何位置。

```yacl
# 这是注释
值: 42   # 行内注释

###
这是多行注释。
可以包含 # 等特殊字符。
以另一个 ### 结束
###

含井号的字符串: '这个 # 不是注释
```

### 多行块

#### 三引号块

三引号块有特定的换行修剪规则：

- 对于 `'''`（三个单引号）和 `"""`（三个双引号），定界符之间的内容**原样保留**，但：
  - 如果开始定界符后面紧跟换行符，则该换行符**被忽略**（开头不会多一个空行）。
  - 如果结束定界符前面有换行符，则该换行符**被忽略**（结尾不会多一个空行）。
- 因此，以下四种写法产生完全相同的值 `"aaa\nbbb"`：

```yacl
x: '''
aaa
bbb
'''

y: '''aaa
bbb
'''

z: '''
aaa
bbb'''

w: '''aaa
bbb'''
```

#### 块标量符号

块标量符号提供了更灵活的多行字符串控制方式，分为两种模式：依赖缩进模式和带行数模式。

##### 基本语法

块标量有两种使用方式：

**1. 依赖缩进模式（不指定行数）**

```
键: |
    文本行1
    文本行2
    文本行3
```

或

```
键: ||
    文本行1
    文本行2
    文本行3
```

在这种模式下，块的内容由**缩进**决定——块从下一行开始，直到缩进回到当前层级为止。

**2. 带行数模式（指定行数）**

```
键: |3
文本行1
文本行2
文本行3
```

或

```
键: ||2
文本行1
文本行2
```

在这种模式下，`|` 或 `||` 后面紧跟一个正整数（如 `|3`、`||5`），表示要提取的行数。**块内容不需要缩进**，从下一行开始逐行读取。

##### `|` —— 保留注释

使用 `|` 时，块内的**所有行**（包括包含 `#` 的行）都被视为字符串内容，注释不会被特殊处理。

**依赖缩进模式示例：**

```yacl
level1:
    text1: |
        我是第一行文本
        我是第二行
        # 我是注释，但是由于是单个管道符（|），所以注释被保留
            我是第四行，但我还是属于text1中的多行文本
    tips: '我和text1键同级，所以我是独立的键值对，不属于多行文本
```

结果：`text1` 的值为 `"我是第一行文本\n我是第二行\n# 我是注释，但是由于是单个管道符（|），所以注释被保留\n    我是第四行，但我还是属于text1中的多行文本"`。

**带行数模式示例：**

```yacl
level2:
    text1: |3
我是第一行文本，由于有行数标注，所以不需要缩进
# 我是注释，但是由于是单个管道符（|），所以注释被保留
     我是第三行，由于有行数标注，空格会被保留下来
    text2: '我是与text1同级的键
```

结果：`text1` 的值为 `"我是第一行文本，由于有行数标注，所以不需要缩进\n# 我是注释，但是由于是单个管道符（|），所以注释被保留\n     我是第三行，由于有行数标注，空格会被保留下来"`（取前 3 行，缩进和注释均保留）。

##### `||` —— 移除注释内容

使用 `||` 时，每行中的 `#` 及之后的内容会被**移除**，但该行本身保留，`#` 之前的内容保留。

**依赖缩进模式示例：**

```yacl
level1:
    text2: ||
        我是第一行文本
        配置项: value # 这行的 # 及之后内容被移除
        key: '我看着是键值对，但是我在text2的缩进下面，所以我还是包含在多行文本里，不是键值对
    key: '我才是真正的键值对，我和text1、text2、tips键同级
```

结果：`text2` 的值为 `"我是第一行文本\n配置项: value \nkey: '我看着是键值对，但是我在text2的缩进下面，所以我还是包含在多行文本里，不是键值对"`（`# 这行的 # 及之后内容被移除` 被移除，但行本身保留）。

**带行数模式示例：**

```yacl
level2:
    text2: ||3
我是第一行文本
配置: debug # 注释被移除，但该行保留
我是第二行文本
# 这整行都是注释，整行移除吗？不，移除 # 及之后内容，该行变为空行
```

结果：`text2` 的值为 `"我是第一行文本\n配置: debug \n我是第二行文本\n"`（注释内容被移除，但行保留；如果整行只有注释，则变为空行）。

##### 详细规则

**依赖缩进模式：**

1. **块起始**：`|` 或 `||` 后直接换行（无数字）。
2. **缩进决定范围**：从下一行开始，所有缩进大于当前键的行都属于该块。
3. **块结束**：当遇到缩进小于或等于当前键的行时，块结束。
4. **空行处理**：空行（仅包含空白字符的行）被保留在最终字符串中。
5. **缩进修剪**：所有行的共同前导缩进会被自动移除（类似 YAML 的块标量）。
6. **注释处理**：
   - `|`（单管道）：保留所有行，`#` 及之后的内容作为字符串的一部分原样保留。
   - `||`（双管道）：移除每行中 `#` 及之后的内容，但行本身保留。

**带行数模式：**

1. **行数指定**：`|` 或 `||` 后面紧跟一个正整数（如 `|3`、`||5`），表示要提取的行数。
2. **不需要缩进**：块内容从下一行开始逐行读取，不需要额外的缩进。
3. **行数计数**：
   - 对于 `|`：所有行（包括空行和注释行）都计入行数。
   - 对于 `||`：所有行都计入行数（即使行中只有注释），但会移除每行中 `#` 及之后的内容；空行（无内容的行）计入行数并保留为空行。
4. **空行处理**：空行（仅包含空白字符的行）计入行数并保留在最终字符串中。
5. **块结束**：达到指定行数后块自动结束，或遇到缩进减少时结束（以先到者为准）。
6. **行数不足**：如果有效行数少于指定的数量，则取所有有效行。

##### 综合示例

```yacl
# 依赖缩进模式

        我是第二行

            我是第四行，但我还是属于text1中的多行文本
    tips: '我和text1键同级，所以我是独立的键值对，不属于多行文本
    text2: ||
        我是第一行文本
        配置: debug # 这行的 # 及之后内容被移除，该行保留
        key: '我看着是键值对，但是我在text2的缩进下面，所以我还是包含在多行文本里，不是键值对
    key: '我才是真正的键值对，我和text1、text2、tips键同级

# 带行数模式
level2:
    text1: |3
我是第一行文本，由于有行数标注，所以不需要缩进
# 我是注释，但是由于是单个管道符（|），所以注释被保留
     我是第三行，由于有行数标注，空格会被保留下来
    text2: ||3
我是第一行文本

我是第二行文本
# 这行只有注释，移除 # 及之后内容后变为空行
```

## 示例

### 完整配置示例

```yacl
# 应用设置
应用:
    名称: 'MyApp
    版本: 1.0.0
    调试模式: enabled

数据库:
    主机: 'localhost
    端口: 5432
    凭证:
        用户: 'admin
        密码: 'secret
        # 密码: 'dummy   # 这行被注释

功能:
    - '身份验证
    - '日志
    - '分析

# 引用第一个功能
默认功能: [功能].0   # => "身份验证"

# 混合类型的嵌套列表
矩阵:
    -
        - 1
        - '二
        - 3.0
    -
        - 4
        - 5
        - '六

# 列表项是对象，对象内部含子列表
服务:
    - 名称: 'api
      端口: 8080
      白名单:
          - '10.0.0.1
          - '10.0.0.2
    - 名称: 'worker
      端口: 8081
      白名单:
```

## 注意事项与边界情况

- **缩进**：可使用空格或制表符，但须保持一致。YACL 使用缩进表示嵌套，与 YAML 类似。在依赖缩进的块标量中，缩进决定了块的边界。
- **列表项对齐**：同一列表的所有 `-` 必须对齐在同一列；缩进不同即视为不同层级。
- **列表项中的 `键:`**：`- 键:` 会把该项解析为**对象**，而不是以 `键:` 开头的字符串。若确实需要这样的字符串项，必须加引号：`- '键: 某值`。
- **对象项内键的对齐**：`- 键:` 之后，同一对象内的其余键需与 `- ` **之后的第一个键**对齐（而非与 `-` 对齐）。若与 `-` 对齐，会被解析为列表的下一项。
- **子列表的缩进**：子列表的 `-` 必须比其所属的 `-` 缩进更深；缩进相同时会被解析为同一层的兄弟项，而不是子列表（见[子列表（嵌套列表）](#子列表嵌套列表)中的对比）。
- **`-` 单独成行**：仅当下一行缩进更深时才合法，该项的内容由后续更深缩进的块决定（以 `-` 开头 → 子列表；以 `键: 值` 开头 → 对象）。若下一行没有更深缩进，该项视为空，建议避免这种写法。
- **`- 键:` 与单独 `-` 等价**：`- 键:` 只是把对象的第一个键写在了短横线后面，两种写法解析结果完全一致。
- **引用中的裸数字**：不带方括号的数字始终作为列表索引；带方括号的数字（如 `[1]`）则作为字符串键 `"1"`。
- **布尔值词元**：区分大小写 —— `True` **不是**布尔值，只有 `true` 才是。
- **双引号字符串中的注释**：在单行双引号字符串（`"..."`）中，`#` 会终止字符串，因此字符串在 `#` 前结束，`#` 及之后的内容被忽略。在三个双引号块中，每行中 `#` 及之后的内容会被移除，但该行保留。
- **空值**：仅 `none` 表示空。
- **引用不存在的键**：行为未定义，实现可返回 `none` 或抛出错误。
- **块标量模式区分**：
  - `|` 或 `||` 后**直接换行**（无数字）→ 依赖缩进模式，缩进决定块范围。
  - `|` 或 `||` 后**紧跟正整数**（如 `|3`、`||2`）→ 带行数模式，块内容不需要缩进。
- **块标量注释处理**：
  - `|`（单管道）：保留所有行，`#` 及之后的内容作为字符串内容保留。
  - `||`（双管道）：移除每行中 `#` 及之后的内容，但该行本身保留；如果整行只有注释（移除后为空），则该行变为空行保留在结果中。
- **块标量嵌套**：在依赖缩进模式中，块标量内容不能包含比当前层级更浅的缩进（否则块会提前结束）。在带行数模式中，块在达到指定行数后结束，或遇到缩进减少时结束（以先到者为准）。
- **行内注释移除**：对于 `||` 块标量和 `"""` 三引号块，注释移除仅影响行内 `#` 及之后的内容，该行本身不会消失，而是保留 `#` 之前的部分（可能为空）。
